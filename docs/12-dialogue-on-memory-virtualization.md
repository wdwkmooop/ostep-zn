# 第 12 章 关于内存虚拟化的对话

> 英文原题：*A Dialogue on Memory Virtualization*

<div class="dialogue" markdown>
**学生：** 那，虚拟化这块儿就算讲完了？

**教授：** 没完！

**学生：** 嘿，犯不着这么激动嘛；我不就是问个问题吗。学生本来就该问问题，对吧？

**教授：** 话是这么说，教授们嘴上也都这么讲，可他们心里的意思其实是：问问题可以，前提是问好问题，而且你得先稍微动过点脑子。

**学生：** 得，您这一盆冷水浇得我透心凉。

**教授：** 任务达成。不管怎么说，虚拟化离讲完还差得远呢！你刚才看到的不过是 CPU 怎么被虚拟化，可实际上，柜子里还蹲着一头大怪物：内存(memory)。虚拟化内存要复杂得多，需要我们弄清硬件与操作系统交互中许多更精妙的细节。

**学生：** 听着挺酷。那为啥这么难？

**教授：** 因为细节一大堆，你得把它们在脑子里理得清清楚楚，才能真的建立起一幅"到底在发生什么"的心智图景。我们先从简单处起步，用基址/界限(base/bounds)这类非常基础的技术，然后慢慢增加复杂度去对付新挑战，包括 TLB 和多级页表(multi-level page table)这些好玩的主题。到最后，我们就能把一套功能完整的现代虚拟内存管理器讲清楚。

**学生：** 太棒了！那对一个被这一堆信息淹没、还普遍睡眠不足的可怜学生，您有啥建议没？

**教授：** 睡眠不足这个好办：多睡觉（少熬夜狂欢）。至于理解虚拟内存，先记住这一点：用户程序产生的每一个地址都是**虚拟地址(virtual address)**。操作系统不过是给每个进程营造一种幻象，尤其是让它以为自己拥有一大块属于自己的私有内存；借助一些硬件帮忙，操作系统会把这些假模假式的虚拟地址变成真正的**物理地址(physical address)**，从而找到想要的信息。

**学生：** 好，我想我能记住……（自言自语）用户程序出来的每个地址都是虚拟的，用户程序出来的每个地址都是虚拟的，每个……

**教授：** 你嘟囔啥呢？

**学生：** 噢，没啥……（一阵尴尬的停顿）……那什么，您再说说，操作系统为啥非要提供这种幻象？

**教授：** 主要是为了好用：操作系统让每个程序都觉得自己拥有一大块连续的**地址空间(address space)**，可以把代码和数据放进去；这样一来，作为程序员，你压根不用操心"这个变量该搁哪儿"之类的问题，因为程序的虚拟地址空间又大又宽敞，放这些东西绰绰有余。要是你非得把所有代码和数据都塞进一块又小又挤的内存里，程序员的日子可就难过多喽。

**学生：** 还有别的原因吗？

**教授：** 再有就是**隔离(isolation)** 和**保护(protection)**，这可是天大的事。我们总不希望一个乱来的程序能去读、甚至更糟——去覆盖别的程序的内存吧？

**学生：** 那估计是不希望。除非那程序是你讨厌的人写的。

**教授：** 嗯……我看下学期得给你课表上再加一门道德伦理课。八成是操作系统课没把该传的道儿传到位。

**学生：** 也许真该加。不过您可记着，教我们"操作系统对乱来进程行为的正确反应就是干掉那个惹事的进程"的，可不是我呀！
</div>
