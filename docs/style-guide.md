# 翻译风格指南

> 目标读者：中文母语、正在学操作系统的大学生。译者要做的是"把那位爱开玩笑的教授
> 用中文再讲一遍"，而不是逐词搬运。

## 1. 总体语气

* **口语、直白、带点痞**。原文 Author 喜欢插科打诨，中文也要有对应的俏皮感。
* 长句拆短。英文用从句堆信息，中文改成几个短句更顺。
* 允许使用网络化但不过分的说法："翻车""坑""踩雷""抓心挠肝""这波操作"。
* 不自造生硬直译，如把 "make the sausage" 硬译成"做香肠"要加注释或换成中文俗语。

## 2. 已确立的风格样例（取自作者旧稿，供模仿）

* "否则,你可学不会! 坚持努力思考, 你才会找到正确方向."
* "炫技容易翻车"
* "代码的奇幻漂流, 让你抓心挠肝,百思不得其解"
* "太糟糕了!"（感叹词照译，保留情绪）
* 边栏标题："术语解释""线程 API 指引"

## 3. 术语处理

* 技术术语**首现**：`中文(english)`，例如 `进程(process)`、`页表(page table)`。
* 之后统一用中文；若中文译名不通用（如 TLB），则保留英文并首现说明。
* **标识符永不翻译**：函数名、变量名、命令行、文件名、结构体名、内核符号。
  * 正确：调用 `fork()` 创建一个子进程。
  * 错误：调用 `派生()` 创建一个子进程。
* 缩写保留大写：TLB、CPU、OS、I/O（或写作"IO"，与旧稿一致处用"IO"）。
* 英文书名、论文标题保留英文，可另附意译。

## 4. 三类框（对应原文排版）

| 原文 | 中文标题 | Material 写法 |
|---|---|---|
| THE CRUX | 问题核心 | `!!! danger "问题核心"` |
| ASIDE | 边栏 | `!!! note "边栏"` |
| TIP | 提示 | `!!! tip "提示"` |

内容里的强调：原文用**粗体**强调处，中文也用粗体；代码标识符用 `` ` ``。

## 5. 对话章

* 一律保留"教授 / 学生"两个角色，格式见 `AGENTS.md` §10。
* 保留所有笑点与打断（"(打断)"、括号动作描写照译）。
* 桃子梗（peach）、云图（Cloud Atlas）等文化梗：直译 + 必要时一句话补白。

## 6. 图、代码、公式

* 图注：`*图 X.Y：<译文>。*`（斜体，前缀"图 X.Y："）。
* 代码：完整转写，语言标注 `c`，不改原书内容。行内讲解用 Material annotation。
  * **代码中的注释一律翻译成中文**，保留注释符号（`//`、`/* */`、`#`）。
  * **代码本身、标识符、字符串字面量、`printf` 输出文本、命令行参数、文件名保持原样**——
    它们要么是程序行为的一部分，要么是标识符，不能改。
  * 例：

    ```c
    int main(int argc, char *argv[]) {
        // 打印命令行参数个数（不含程序名本身）
        printf("argc = %d\n", argc);
        return 0;
    }
    ```
* 公式：少量，用 `$...$`；分段公式用 `$$...$$`。
* 命令行/输出：用 `console` 或 `text` 代码块，保留 `prompt>` 等提示符原样。

## 7. 参考文献与作业

* **参考文献**：英文条目原样保留（作者、标题、出处），其后的**吐槽式批注翻译成中文**。
  例：`[M04] 《Cloud Atlas》……如果不用功读书，你迟早会后悔的。`
* **作业（Homework）**：正文与题目翻译；模拟器命令、文件名、参数**保留英文**。
  例："运行 `./scheduler.py -p SJF` 回答以下问题。"

## 8. 数字、单位、命名

* 数字与单位保持原文习惯：`10 ms`、`4 KB`、`0x1000`。
* 代码中出现的十六进制、二进制不加中文。
* 章节交叉引用译作"第 X 章""第 X.Y 节"。

## 9. 标点

* 正文用**中文全角标点**（，。：；""），但代码、命令、英文短语内部用半角。
* 中英相邻时不加空格（"使用 fork() 创建"可加可不加，全篇统一为**加一个空格**）。
* 破折号用"——"。
