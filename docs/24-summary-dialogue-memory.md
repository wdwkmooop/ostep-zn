# 第 24 章 内存虚拟化总结对话

> 英文原题：*Summary Dialogue on Memory Virtualization*

<div class="dialogue" markdown>

**学生：**（咽了口唾沫）哇，这内容也太多了吧。

**教授：** 是啊，然后呢？

**学生：** 可……我怎么可能全记住啊？您知道的，就为了考试。

**教授：** 老天，我希望你记这些东西不是为了考试。

**学生：** 那我图啥？

**教授：** 拜托，我还以为你比这明白。你在这儿是要学点真本事——等你哪天走向外面的世界，才能搞懂系统到底是怎么运转的。

**学生：** 嗯……能举个栗子吗？

**教授：** 当然！有一回读研究生的时候，我跟几个朋友在测一次内存访问(memory access)要花多长时间。可时不时地，测出来的数字比我们预想的要高出一大截；你想啊，我们本以为所有数据都舒舒服服地躺在二级硬件缓存(second-level hardware cache)里，那访问起来应该快得很才对。

**学生：**（点头）

**教授：** 我们死活想不通到底怎么回事。这种时候你怎么办？好办，问教授去！于是我们跑去找了一位教授，他瞅了一眼我们画的图，就轻描淡写地吐出三个字母："TLB"。啊哈！可不就是 TLB 缺失(TLB miss)嘛！我们怎么就没往这儿想呢？有一套关于虚拟内存(virtual memory)如何工作的心智模型(mental model)，能帮你诊断出各种各样有意思的性能问题。

**学生：** 我好像有点明白了。我是在脑子里搭这些"东西到底怎么运转"的模型，这样一来，等将来独自在外面干活，撞上系统不按预期出牌时，也不至于一脸懵。我甚至应该光靠脑子推演，就能预判系统会怎么跑。

**教授：** 正是如此。那你说说，你都学到了啥？关于虚拟内存怎么工作，你脑子里的模型里都有些什么？

**学生：** 嗯，我想我现在挺清楚当一个进程引用内存时会发生什么了——就像您说过好多遍的，每一次取指令，还有显式的 load 和 store，都会触发这套流程。

**教授：** 听着不错——接着讲。

**学生：** 嗯，有一点我这辈子都会记得：我们在用户程序里看到的所有地址，比如用 C 写的那种……

**教授：** 还能是别的什么语言？

**学生：**（继续）……对，我知道您偏爱 C。我也爱！总之，我刚才说，我现在是彻底明白了：程序里能观察到的一切地址都是**虚拟地址(virtual address)**；作为程序员的我，拿到的不过是"数据和代码待在内存哪儿"这么一个假象。以前我觉得能打印出一个指针的地址挺酷的，现在我只觉得憋屈——那玩意儿不过是个虚拟地址！数据真正待在哪块**物理地址(physical address)**上，我根本瞧不见。

**教授：** 瞧不见就对了，操作系统铁定要把这个瞒着你。还有呢？

**学生：** 嗯，我觉得 TLB——也就是**快表(TLB)**——是特别关键的一块拼图，它给系统提供了一个小小的硬件缓存，专门缓存地址转换结果。页表(page table)一般个头都不小，所以只能待在大而慢的存储器里。要是没有这块 TLB，程序的运行速度铁定要慢上一大截。感觉正是 TLB 才让虚拟化内存成为可能。我实在没法想象搭一套系统却不要它！一想到某个程序的**工作集(working set)** 大得超出了 TLB 的覆盖范围，我就直打哆嗦：那满屏的 TLB 缺失，简直不忍直视。

**教授：** 是啊，快把孩子们的眼睛捂上！除了 TLB，你还学到了什么？

**学生：** 我还明白了，页表也不过是你需要了解的那种数据结构罢了；它终究只是个数据结构，这意味着理论上几乎任何结构都能拿来用。我们从最简单的结构起步，比如数组（也就是线性页表(linear page table)），一路升级到多级页表(multi-level page table)（看起来像棵树），甚至更离谱的玩意儿，比如放在内核虚拟内存里、可换出的页表。搞这一切，就为了在内存里省下那么一丁点空间！

**教授：** 没错。

**学生：** 还有一点也很重要：我发现这些地址转换结构得足够灵活，才能支撑程序员想对自己的地址空间做的那些事。从这个角度说，多级页表这类结构就完美合拍；只有当用户需要地址空间的某一部分时，它才会创建对应的表空间，所以几乎不浪费。早先那些尝试，比如简单的基址与界限寄存器(base and bounds register)，就是不够灵活；这些结构必须贴合用户对自己虚拟内存系统的期待和要求。

**教授：** 这个视角不错。那关于交换到磁盘(swap)的那些内容呢？

**学生：** 嗯，研究起来确实挺好玩，搞懂页替换(page replacement)怎么工作也很有收获。有些基本策略明摆着就是那么回事（比方说最近最少使用(LRU)），但要真搭出一套能用的虚拟内存系统，感觉就有意思多了，就像我们在 VMS 案例研究里看到的那样。不过不知怎么的，我总觉得机制(mechanism)更有意思，策略(policy)反而差点意思。

**教授：** 哦？这话怎么说？

**学生：** 嗯，就像您说的，说到底，策略问题的最佳解法特别简单：多买点内存。可机制不一样，你得真弄懂它才能明白东西到底是怎么运转的。说到这个……

**教授：** 嗯？

**学生：** 那个……我最近这台机器跑得有点慢……再说了，内存现在也真不贵……

**教授：** 行行行，得了得了！给你几张票子。自己去买点 DRAM，你这铁公鸡。

**学生：** 谢谢教授！我再也不往磁盘上交换了——就算真换了，起码我也知道到底发生了啥！
