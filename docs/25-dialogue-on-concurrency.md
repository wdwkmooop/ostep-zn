# 第 25 章 关于并发的对话

> 英文原题：*A Dialogue on Concurrency*

<div class="dialogue" markdown>

**教授：** 于是，我们来到了操作系统三根支柱中的第二根：并发(concurrency)。

**学生：** 我还以为有四根支柱来着……？

**教授：** 没有，那是旧版书里的说法。

**学生：** 呃……好吧。那么，尊敬的教授，并发究竟是什么？

**教授：** 嗯，想象一下，我们有一只桃子——

**学生：**（打断）又是桃子！您跟桃子到底有什么不解之缘？

**教授：** 读过 T. S. 艾略特吗？《J. 阿尔弗雷德·普鲁弗洛克的情歌》里那句“我敢吃一只桃子吗”，还有诸如此类的妙句？

**学生：** 当然读过！高中英语课上学的。写得真棒！我尤其喜欢那段——

**教授：**（打断）这跟那首诗半点关系也没有——我就是喜欢桃子。总之，想象桌上摆着一大堆桃子，又有一大群人想吃。假设大家这么干：每个吃桃群众先用眼睛锁定一只桃子，再伸手去抓来吃。这个办法有什么问题？

**学生：** 嗯……你看中的桃子，可能也被别人看中了。要是他先下手，等你伸手时，桃子早没影了！

**教授：** 正是！那该怎么办？

**学生：** 大概得想个更靠谱的办法。比如排成一队，轮到谁站到最前面，谁就拿一只桃子走人。

**教授：** 很好！可你的办法又有什么毛病？

**学生：** 不是吧，活儿都得我一个人干？

**教授：** 对。

**学生：** 好吧，让我想想。之前是一群人同时抢桃子，速度快；按我的办法，大家一次只能来一个，倒是不会出错，可慢了不少。最理想的办法，应该既快又正确。

**教授：** 你真是越来越让我刮目相看了。事实上，你刚才已经把并发要教给我们的东西全说完了！干得漂亮。

**学生：** 我说完了？我还以为我们只是在聊桃子。您是不是忘了，通常到这里，该把话题拽回计算机了？

**教授：** 确实如此，抱歉！永远别忘了落到实处。事情是这样的：有一类程序叫**多线程应用程序(multi-threaded application)**；每条线程(thread)都像一个独立的小代理，在程序里四处奔忙，替程序办事。可这些线程都要访问内存，对它们来说，每个内存位置就像桌上的一只桃子。如果不协调线程对内存的访问，程序就不会按预期工作。明白了吗？

**学生：** 大概吧。不过我们为什么要在操作系统课里讲这个？这不只是应用程序编程的问题吗？

**教授：** 问得好！其实有几个原因。第一，操作系统必须用锁(lock)、条件变量(condition variable)之类的原语支持多线程应用，我们很快就会讲到。第二，操作系统本身就是最早的并发程序——它必须极其小心地访问自己的内存，否则各种诡异又可怕的事情都会冒出来。真的，那场面会相当血腥。

**学生：** 懂了，听起来挺有意思。我猜，还有不少细节吧？

**教授：** 那当然……
