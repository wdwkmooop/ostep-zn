# 第 11 章 CPU 虚拟化总结对话

> 英文原题：*Summary Dialogue on CPU Virtualization*

<div class="dialogue" markdown>

**教授：** 那么，学生，你学到点东西没有？

**学生：** 呃，教授，这问题问得可有点设套。我觉得您就等着我说"学到了"呢。

**教授：** 这倒是真的。但这问题本身也是真心想问的。行行好，给教授一个台阶下，行不行？

**学生：** 好好好。我想我确实学到了一些东西。首先，我大概弄明白了操作系统是怎么把 CPU **虚拟化(virtualization)** 的。为了搞懂这套东西，我得先理解一堆重要的**机制(mechanism)**：**陷阱(trap)** 和**陷阱处理程序(trap handler)**、**时钟中断(timer interrupt)**，还有操作系统和硬件在**进程(process)** 之间切换时，必须小心翼翼地保存和恢复**状态(state)**。

**教授：** 好，好！

**学生：** 不过这些交互看着还是有点复杂；我该怎么做才能学得更多呢？

**教授：** 嗯，这是个好问题。我觉得动手实践无可替代；光靠读这些东西，是练不出那种手感的。把课程项目做一做，我打赌做完之后，一切就都豁然开朗了。

**学生：** 听起来不错。还能再跟您聊点别的吗？

**教授：** 那……在你探索操作系统基本机器的过程中，感受到它背后的那套哲学了吗？

**学生：** 嗯……我想是的。操作系统好像挺偏执的。它一门心思想确保自己牢牢掌控着这台机器。它既想让程序尽可能高效地跑（于是有了**受限制的直接执行(limited direct execution)** 这一整套道理），又想在碰上跑偏的或心怀恶意的进程时，能甩出一句"哎！想得美，朋友"。偏执当道啊，而正是这份偏执让操作系统稳坐老大之位。也许正因为如此，我们才把操作系统看作**资源管理器(resource manager)**。

**教授：** 没错——听着你开始把这些线索串起来了嘛！不错。

**学生：** 谢谢。

</div>

<div class="dialogue" markdown>

**教授：** 那这些机制之上的**策略(policy)** 呢——有没有什么有意思的体会？

**学生：** 体会肯定有。也许有点浅显，但浅显也有浅显的好。就拿把短作业插到队列前面这个思路来说吧——自从那次我在店里买口香糖，前面那位老兄的信用卡怎么刷都刷不过去，我就知道这主意准没错。跟您说，他可真是个不折不扣的长作业。

**教授：** 这话对那位可怜人可有点刻薄了。还有呢？

**学生：** 还有，就是你能造出一个聪明的**调度器(scheduler)**，让它既想像**最短作业优先(SJF)** 又想像**轮转(RR)**——那个**多级反馈队列(MLFQ)** 就挺妙的。不过真要搭出一个能用的调度器，看起来可不容易。

**教授：** 确实不容易。正因如此，到今天人们还在为到底该用哪个调度器争得不可开交；比如 Linux 世界里 **CFS**、**BFS** 和 **O(1)** 调度器之间的那几场大战。另外，BFS 的全称我是不会给你拼出来的。

**学生：** 我也绝不会求您拼！这些策略之争好像能吵到天荒地老；难道真有一个标准答案吗？

**教授：** 大概没有。说到底，就连我们自己的指标都互相对着干：你的调度器**周转时间(turnaround time)** 好，**响应时间(response time)** 就差，反过来也一样。正如 Lampson 所说，也许目标并不是找到最优解，而是避免灾难。

**学生：** 这话听着有点丧。

**教授：** 好的工程就是这样，有时让人丧气，有时又令人振奋！说到底，就看你从哪个角度看了。我个人觉得务实是件好事，务实的人也明白：不是所有问题都有干净利落的简单解。还有别的什么让你眼前一亮吗？

**学生：** 我特别喜欢**钻调度器空子(gaming the scheduler)** 这个思路；下次我在亚马逊的 EC2 服务上跑作业时，说不定可以研究研究。也许我能从别的毫无戒心（更重要的是，对操作系统一无所知）的客户那儿偷点 CPU 周期！

**教授：** 看来我好像亲手造出了一个怪物！你知道的，我可不想被人叫做弗兰肯斯坦教授。

**学生：** 可这不正是您的初衷吗？让我们对某样东西兴奋到不行，以至于自己主动去钻研？点燃我们心里的小火苗，诸如此类？

**教授：** 大概吧。可我没想到它真能奏效！

</div>
